Bench Boards

A visual, pin-and-fork feed for lab protocols and the parts they need, built as a view over the BaeBugs graph so every card carries its own hash, licence and twin check.

Scope: next feature after the hackathon MVP. Nothing here is built yet. Grounded in mvp-kg at bffec50 and the bench-twin files in the project folder.

The idea in one paragraph

Protocol sites today are long text pages. Researchers actually choose a method the way people browse Pinterest: by looking at the rig, the deck layout and the result, then saving it for later. Bench Boards shows each protocol, printable part, labware definition, insect print and model as a card with a picture, a few visual steps, a cost, and a custody chip. You pin cards to boards ("Pollinator bag sort under $200"), fork a card to make your own version, and press Check in twin to see whether it would run on your bench before anything moves.

Why BaeBugs can do this cheaply. The hard part of such a site is trust: is this the file the author ran, under what licence, did it work? BaeBugs already answers that for every file. The AoK graph has 868 atoms, each with a sha256, a claim (799 OWN, 20 THIRD), a licence and a status (736 built, 83 tested, 17 frozen, 12 result, 20 reference). A card is just a nicer face on one or more of those leaves.

What a card is

  
Every card is a small bundle of fragments, hashed with the same rules the bench twin already uses: canonical JSON, leaf = SHA-256(0x00 ‖ name ‖ \n ‖ JSON), node = SHA-256(0x01 ‖ left ‖ right), fragments sorted by name. So verify.py logic carries over unchanged.


card
  kind        protocol | part | labware | bug_print | model | agent | study
  leaves      [leaf:opentrons/protocols/baebugs_flex_line.py, ...]   # must resolve to stored bytes, else BREAK
  media       preview image or SVG, rendered from the STL / deck / GLB
  steps       [{text, kind: action|pause, module, params}]           # parsed from protocol.comment / pause
  needs       [card roots of parts, labware, instruments]
  cost        {usd, basis, est: true}                                # from bench-twin filament table
  licence     {claim: OWN|THIRD, licence, effect}                    # copied from the AoK atom
  derivation  [parent card roots]                                    # a fork; same as a remix today
  status      built | tested | frozen | result | BREAK
card_root = merkle(fragments)

  
Boards are an ordered list of card roots with a title. Each pin, unpin and fork is appended to an MMR log, the same structure as the existing daisy/*_mmr.jsonl logs, so a board's history replays and its root goes into the MVP root like every other log.

Against the AI Mode brief

  
Byron's pasted architecture brief covers the generic version of this app. Most of it fits. Where it differs, the reason is the same each time: in BaeBugs a hash the graph references must resolve to stored bytes, so the database, the media store and the AI helpers can serve cards but can never be the record.

First domain: insect sample prep and printable lab hardware

  
The brief asks which field to start in. My proposal is entomology sample prep (“bags in, barcodes out”) together with fabrication of the hardware it needs. Every card in the mockup already exists in the repo for this field: the Flex protocol, 4 Opentrons parts, 8 bench-twin remixes, the Fuse 1 insect prints, 31 filter types and the DAISY studies. It is also the use case for the BioKEA novel-bug-finder submission and the preprint. Molecular biology follows naturally from the lysis and 56 °C soak steps, which are where the hazard tags and timers first matter.


  
Discovery without a social network

  
Ranking should reward evidence, not likes. Proposed order of signals:

  
    
    
  • Status: tested and result cards above built; any card with a BREAK is shown, but labelled and never ranked first.
    • 
    
  • Twin passes on other benches: count of distinct bench profiles whose preflight passed, read from the custody log.
    • 
    
  • Forks that kept going: a fork that later reaches tested counts for its parent.
    • 
    
  • Contests: an open contest issue on any leaf lowers the card until it is answered.
    • 
    
  • Facets: kind, BioKEA module (1 to 5), taxon family, hardware (Flex, Partabot, Fuse 1), and a “kit under $200” filter summed over needs.
    • 
  


  
Build plan

  
v0
Read-only gallery. python -m baebugs.cards reads site/mvp/mvp.json and writes site/cards/cards.json; a static page renders the masonry feed and detail pane. Deploys on Vercel next to the MVP graph. Cards for the Flex protocol, 4 Opentrons parts, 8 bench-twin remixes, the Fuse 1 insect prints, 31 filter types and the DAISY preregs. Ships with a replay notebook that swaps in any mvp.json. About 2 days.

  
v1
Boards and forks. Boards stored as JSON in the repo and changed by pull request, so the git ledger is the write log. Fork creates a new card with a derivation fragment. About 3 days.

  
v2
Check in twin. A Vercel function runs the preflight against a saved bench profile and returns the break point, plus a 3D replay of the run over time from print/bench/bench.glb and demo_run.json. About 1 week.

  
v3
Outside contributors. Submit a card from a GitHub repo, a Hugging Face model or a protocols.io DOI; a hosted board for the BioKEA novel-bug-finder submission and the Heterodox Labs style use case in the preprint.
